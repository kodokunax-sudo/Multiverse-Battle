# Multiverse Battle — настройка онлайн-кланов

Теперь есть профили игроков с аватарами, игровой статистикой и клановый чат в реальном времени. Статистика берётся из локального сохранения и не считается защищённой от читов.

## Что нужно сделать один раз

1. Создай бесплатный проект на https://supabase.com/dashboard. Бесплатные проекты могут приостанавливаться после недели неактивности.
2. Для нового проекта открой SQL Editor и выполни SQL-файлы из supabase/migrations по порядку: сначала 20261010000000_clans.sql, затем 20261010150000_profiles_chat.sql и 20261010170000_chat_user_index.sql. В уже настроенном проекте вторая миграция будет применена отдельно.
3. В репозитории уже настроен supabase-config.js с URL проекта и публичным publishable key. При смене ключа обнови только этот файл. Никогда не используй service_role или secret key во фронтенде.
4. В Authentication → URL Configuration укажи домен, на котором опубликована игра, в Site URL и Redirect URLs. Для GitHub Pages используй полный URL сайта. Для локального тестирования добавь используемый локальный адрес.
5. В Authentication → Providers → Email оставь включённым Email. Если подтверждение почты включено, новый игрок должен открыть ссылку из письма перед первым входом. Встроенная отправка писем Supabase имеет лимиты; для публичного запуска это нужно будет отдельно настроить.
6. Перезагрузи игру и открой вкладку 🛡️ Кланы. Зарегистрируй два тестовых аккаунта и проверь создание клана, вступление, выход и роспуск лидером.

## Что есть в первом этапе

- Регистрация и вход по электронной почте и паролю.
- Создание клана с названием, тегом и описанием.
- Список кланов и число участников.
- Вступление в один клан, просмотр состава и выход.
- Лидер может распустить свой клан.
- Редактируемый профиль: имя, описание и аватар из существующих изображений персонажей в images.js.
- Публичный просмотр профиля соклановца: аватар, описание и статистика.
- Клановый чат с историей в базе и доставкой сообщений в реальном времени; отправлять и читать сообщения могут только участники этого клана.
- Лидер не может случайно покинуть клан: передача лидерства пока не входит в MVP.
- Все изменения состава выполняются через RPC-функции с проверками прав на стороне базы.

## Проверки безопасности

- Неаутентифицированный клиент не имеет доступа к таблицам кланов.
- Вошедшие пользователи могут читать базовые данные кланов и составы.
- Прямые INSERT, UPDATE, DELETE клановых таблиц у клиента отозваны.
- Чат использует RLS: читать и отправлять сообщения могут только участники указанного клана; нельзя отправить сообщение от чужого аккаунта.
- Доступные RPC-функции используют SECURITY DEFINER, пустой search_path, полные имена таблиц и явные проверки пользователя.
- В конфигурации никогда не нужно помещать service-role или secret key.

## Что ещё не реализовано

Онлайн-статус, модерация чата и рейтинги побед над боссами ещё не реализованы. Текущая игровая статистика синхронизируется из клиентского сохранения и может быть изменена владельцем через инструменты браузера; её не следует использовать как серверно подтверждённый рейтинг или выдавать за честный соревновательный результат.

## Быстрая диагностика

- «Онлайн-кланы почти готовы, но Supabase ещё не настроен» — проверь URL и публичный ключ в supabase-config.js.
- relation does not exist — миграция не выполнена в том Supabase-проекте, URL которого внесён в конфиг.
- Не приходит письмо — проверь подтверждение почты, Site URL и Redirect URLs в Auth settings.
- Ошибка подключения — проверь URL, ключ, доступ в сеть и консоль браузера.
