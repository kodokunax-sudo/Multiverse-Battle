# Multiverse Battle — настройка онлайн-кланов

Первая версия добавляет аккаунты и базовые кланы. Рейтинг, чат и статус «онлайн» остаются следующими этапами.

## Что нужно сделать один раз

1. Создай бесплатный проект на https://supabase.com/dashboard. Бесплатные проекты могут приостанавливаться после недели неактивности.
2. Открой SQL Editor в проекте Supabase и выполни весь файл supabase/migrations/20261010000000_clans.sql из этого репозитория.
3. В Project Settings → API скопируй Project URL и публичный publishable key (или legacy anon key). Не используй service_role или secret key во фронтенде.
4. В supabase-config.js замени YOUR_PROJECT_ID и YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY на эти значения. URL и публичный ключ предназначены для браузера; безопасность данных обеспечивают политики RLS и проверки функций PostgreSQL.
5. В Authentication → URL Configuration укажи домен, на котором опубликована игра, в Site URL и Redirect URLs. Для GitHub Pages используй полный URL сайта. Для локального тестирования добавь используемый локальный адрес.
6. В Authentication → Providers → Email оставь включённым Email. Если подтверждение почты включено, новый игрок должен открыть ссылку из письма перед первым входом. Встроенная отправка писем Supabase имеет лимиты; для публичного запуска это нужно будет отдельно настроить.
7. Перезагрузи игру и открой вкладку 🛡️ Кланы. Зарегистрируй два тестовых аккаунта и проверь создание клана, вступление, выход и роспуск лидером.

## Что есть в первом этапе

- Регистрация и вход по электронной почте и паролю.
- Создание клана с названием, тегом и описанием.
- Список кланов и число участников.
- Вступление в один клан, просмотр состава и выход.
- Лидер может распустить свой клан.
- Лидер не может случайно покинуть клан: передача лидерства пока не входит в MVP.
- Все изменения состава выполняются через RPC-функции с проверками прав на стороне базы.

## Проверки безопасности

- Неаутентифицированный клиент не имеет доступа к таблицам кланов.
- Вошедшие пользователи могут читать базовые данные кланов и составы.
- Прямые INSERT, UPDATE, DELETE клановых таблиц у клиента отозваны.
- Доступные RPC-функции используют SECURITY DEFINER, пустой search_path, полные имена таблиц и явные проверки пользователя.
- В конфигурации никогда не нужно помещать service-role или secret key.

## Что ещё не реализовано

Рейтинг, очки за победы над боссами, клановый чат и Realtime Presence (онлайн-статус) не входят в этот этап. Их следует строить следующим этапом на серверно проверяемых данных, чтобы клиент не мог подделывать очки.

## Быстрая диагностика

- «Онлайн-кланы почти готовы, но Supabase ещё не настроен» — проверь URL и публичный ключ в supabase-config.js.
- relation does not exist — миграция не выполнена в том Supabase-проекте, URL которого внесён в конфиг.
- Не приходит письмо — проверь подтверждение почты, Site URL и Redirect URLs в Auth settings.
- Ошибка подключения — проверь URL, ключ, доступ в сеть и консоль браузера.
